## 12.1 两类验证

RepoLens 有两套互补的验证：

```text
tests/     单元测试：函数级、边界、回归
evals/     多仓库评测：端到端扫描事实指标
```

它们都不调用大模型。

为什么：

- 确定性；
- 快；
- 不消耗 API；
- 失败可复现。

## 12.4 一个测试长什么样

```python
class ScannerTests(unittest.TestCase):
    def test_demo_repo_has_core_facts(self):
        snapshot = demo_snapshot()
        names = {tech.name for tech in snapshot.techs}
        self.assertIn("FastAPI", names)
        self.assertIn("React", names)
```

步骤：

```text
准备输入
→ 调用函数
→ 断言输出
```

尽量一个测试只测一件事。

## 12.5 测试夹具

`tests/support.py`：

```python
DEMO_REPO = PROJECT_ROOT / "examples/demo_shop"

def demo_snapshot():
    return scan_repository(DEMO_REPO, "examples/demo_shop", "local")

def demo_report():
    snapshot = demo_snapshot()
    ctx = AnalysisContext(...)
    ctx.snapshot = snapshot
    return build_report(ctx)
```

为什么复用：

- 不需要每个测试都扫描；
- demo 仓库稳定；
- 报告结构与真实一致。

## 12.6 临时目录

涉及写文件/SQLite 的测试，用 `tempfile`：

```python
with tempfile.TemporaryDirectory() as tmp:
    root = Path(tmp)
    ...
```

不要写到真实的 `data/`。
测试结束自动清理。

## 12.7 测试哪些边界

以代码查看器为例：

```text
正常文件 + 行号
路径穿越 ../
敏感文件 .env
仓库外文件
缺失文件
.git/config
二进制/大文件
```

以报告为例：

```text
schema_version
旧报告没有 module_graph
旧报告没有 layer/function
JSON 保存/读取
SQLite 索引
```

以引用核对为例：

```text
有效引用
伪造路径
错误行号
无引用
混合引用
```

**边界比 happy path 更重要。**

## 12.8 多仓库评测

命令：

```powershell
..\.venv\Scripts\python.exe scripts\evaluate.py --out evals\latest.json --md evals\latest.md
```

当前 4 个用例：

```text
demo_shop   Python / FastAPI / React / PostgreSQL / Redis / Docker
node_api    JavaScript / Express / Vitest
go_service  Go / Gin / Docker
rust_cli    Rust / serde
```

指标：

- 技术召回；
- 语言；
- 入口文件；
- 文件数 / LOC；
- 依赖图节点/边；
- 证据覆盖；
- 截断；
- `extra_techs`（信息性）。

通过条件：

```text
期望技术/语言/入口全部命中
文件/LOC/图达到下限
证据覆盖达到阈值
```

失败时退出码 1。

## 12.9 为什么还需要评测

单元测试通常只测函数：

```text
parse_requirements 返回 3 个依赖
```

评测测整个扫描器：

```text
在一个真实的小仓库里，能不能识别 Go / Gin / Docker
入口文件对不对
依赖图是否退化
```

它防止：

- 改一个正则，修好 Python，弄坏 Go；
- 改入口识别，demo 通过但 Node 失败；
- 改扫描上限，指标悄悄下降。

## 12.10 增加一个测试

场景：给 `risk.py` 增加“无 CI”规则。

步骤：

1. 构造最小 report；
2. 调用 `build_risk_panel(report)`；
3. 断言 finding；
4. 断言 severity/counts。

模板：

```python
def test_missing_ci(self):
    data = build_risk_panel({"techs": [], "risks": [], "warnings": []})
    titles = [item["title"] for item in data["findings"]]
    self.assertTrue(any("CI" in title for title in titles))
```

## 12.11 增加一个评测用例

1. 放一个很小的 fixture 仓库到 `evals/fixtures/`；
2. 在 `evals/cases.json` 增加 case；
3. 写期望技术/语言/入口/下限；
4. 先跑单例，确认真实输出；
5. 不要凭猜写 expected。

示例：

```json
{
  "id": "my_fixture",
  "path": "evals/fixtures/my_fixture",
  "expected": {
    "techs": ["Python"],
    "languages": ["Python"],
    "entry_points": ["main.py"],
    "min_files": 2,
    "min_loc": 5
  }
}
```
