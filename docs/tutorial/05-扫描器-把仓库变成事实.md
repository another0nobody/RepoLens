# 第 05 章：扫描器——把仓库变成事实

> 阅读时间：90–120 分钟  
> 前置：第 04 章  
> 目标：理解 `scanner.py` 如何从文件得到技术、证据和依赖图

---

## 5.1 一句话

> 扫描器不调用大模型，它只做确定性的事：数文件、读清单、提取 import、匹配技术、记录证据。

它是整个项目最“笨”也最可靠的一层。

---

## 5.2 为什么需要扫描器

模型可以读代码，但：

- 上下文有限，几千个文件读不完；
- 可能编造文件名/版本；
- 同一个仓库两次回答可能不同；
- 无法保证每项技术都带行号。

扫描器提供：

```text
文件数 / 代码行数 / 语言
依赖清单
技术候选
模块路径 + 行号
证据原文
入口文件
模块依赖图
```

Agent 的工作是“解释这些事实”，不是“重新发现这些事实”。

---

## 5.3 入口：scan_repository

核心签名：

```python
def scan_repository(
    root: Path,
    source: str,
    source_type: str,
    progress: Progress = None,
) -> Snapshot:
```

流程：

```text
遍历目录
→ 过滤忽略项
→ 统计文件/语言/LOC
→ 解析清单
→ 提取 import
→ 匹配技术
→ 检测代码使用
→ 构建模块依赖图
→ 找入口/目录/README
→ 返回 Snapshot
```

源码：`repolens/scanner.py`。

---

## 5.4 遍历目录

### 忽略目录

```python
IGNORE_DIRS = {
    ".git",
    "node_modules",
    "dist",
    "build",
    "out",
    "target",
    "venv",
    "__pycache__",
    "site-packages",
    "vendor",
    ...
}
```

为什么忽略：

- `.git` 不是项目源码；
- `node_modules` 可能有几万文件；
- `dist/build` 是构建产物；
- 虚拟环境不属于项目。

### 允许的点目录

```python
ALLOW_DOT_DIRS = {".github", ".gitlab", ".devcontainer", ".circleci"}
```

因为这些可能包含 CI / 开发环境配置，是值得分析的事实。

### 忽略文件名

```python
IGNORE_FILENAMES = {
    "package-lock.json",
    "pnpm-lock.yaml",
    "yarn.lock",
    "poetry.lock",
    "cargo.lock",
    ...
}
```

锁文件通常很大且与清单重复，扫描器默认跳过它们，避免把同一批依赖重复计数；版本主要来自清单本身。

### 上限

```python
MAX_FILES = 8000
MAX_CONTENT_FILES = 2600
MAX_FILE_BYTES = 600_000
```

目的：

- 防止误选系统目录；
- 控制内存/时间；
- 超大仓库截断，并在报告中标记。

## 5.5 语言与代码行数

```python
LANGUAGE_BY_SUFFIX = {
    ".py": ("Python", True),
    ".ts": ("TypeScript", True),
    ".vue": ("Vue", True),
    ".md": ("Markdown", False),
    ...
}
```

第二个布尔值表示“是否算代码语言”。

因此：

- Python / TypeScript 进入代码行数；
- Markdown / JSON / YAML 不计入代码行数；
- 报告里的“编程语言”只统计代码语言。

## 5.6 解析依赖清单

扫描器支持的清单：

| 生态 | 文件 |
| --- | --- |
| Python | `requirements*.txt`、`pyproject.toml`、`setup.py`、`setup.cfg`、`Pipfile` |
| JS/TS | `package.json` |
| Java | `pom.xml`、`build.gradle(.kts)` |
| Go | `go.mod` |
| Rust | `Cargo.toml` |
| PHP | `composer.json` |
| Ruby | `Gemfile` |
| .NET | `*.csproj` |
| 容器 | `Dockerfile`、`docker-compose.yml` |

解析结果：

```python
@dataclass
class DepRef:
    name: str
    version: str
    path: str
    line: int
    ecosystem: str
```

它记录“依赖名 + 版本 + 清单文件 + 行号”。

### 为什么清单很重要

`package.json` 里出现 `"react": "^18.3.1"`，就是 React 的强证据。  
比模型“猜这个项目用了 React”可靠得多。

## 5.7 提取 import

Python 使用 `ast`：

```python
tree = ast.parse(text)
for node in ast.walk(tree):
    if isinstance(node, ast.Import):
        ...
    elif isinstance(node, ast.ImportFrom):
        ...
```

JS/TS 等项目使用正则提取：

```text
import ... from "..."
require("...")
from "..." import ...
```

结果：

```python
@dataclass
class ImportRef:
    name: str
    path: str
    line: int
    snippet: str
```

它回答：

```text
哪个文件、哪一行、导入了什么
```

## 5.8 匹配技术：从名字到 TechHit

`catalog.py` 是一张技术词典：

```python
T("Redis", "缓存与消息", ("redis", "redis-py"), "内存缓存/消息", "any")
```

匹配规则：

1. 精确匹配（忽略大小写、下划线/短横线）；
2. 前缀匹配（如 `spring-boot-starter-web` → Spring Boot）；
3. 找不到时归入“其他依赖”。

匹配来源：

```text
依赖清单
import
Docker 镜像
代码符号/连接串
```

汇总成：

```python
TechHit(
    key="redis",
    name="Redis",
    category="缓存与消息",
    version="5.0",
    confidence="高",
    modules={"backend/app/cache.py": {...}},
    evidence=[...],
    usage_tags={"缓存"},
)
```

### 置信度

大致规则：

```text
清单 + import + 代码使用 → 高
清单 + import            → 高/中
只有清单                  → 中
只有 AI 推断              → 低 / ai_inferred
```

具体逻辑在 `scanner.py` 和 `report.py` 中，不需要一次背完。

## 5.9 代码实际使用：不止 import

有些技术不是通过 import 出现的：

```python
cache = RedisCache(...)
client = redis.Redis(host="localhost", port=6379)
url = "redis://localhost:6379/0"
```

扫描器会检测：

- 符号调用；
- 连接串；
- 用途标签（缓存 / 消息 / 数据库 等）。

代码：`detect_code_usages()`。

这就是为什么 README 只写“Redis 缓存”，项目也能识别出 Redis。

## 5.10 模块依赖图

`_build_module_graph()` 把本地 import 变成有向图：

```json
{
  "nodes": [
    {"path": "backend/app/main.py", "in_degree": 0, "out_degree": 1}
  ],
  "edges": [
    {"source": "backend/app/main.py", "target": "backend/app/api/routes.py"}
  ],
  "stats": {"node_count": 10, "edge_count": 11, "cycle_count": 0}
}
```

用途：

- 依赖图 Tab；
- 先看什么（按入边/出边挑核心文件）；
- 风险面板（循环依赖）；
- 报告对比（模块边变化）。

限制：

- 只解析本地 import；
- 动态 import、路径别名可能漏；
- 最多 160 节点 / 1200 边。

## 5.11 入口、目录与 README

### 入口文件

`_find_entry_points()` 识别：

```text
main.py / app.py / server.py / run.py
index.js / main.ts / main.tsx
app.tsx / app.vue
main.go / main.rs
Dockerfile / docker-compose.yml
package.json / requirements.txt
...
```

最多 12 个。

### 目录规模

`top_dirs`：

```json
[{"name": "backend", "files": 7, "loc": 120}]
```

### README

读取 README 的一部分，供 Agent 参考项目说明。  
注意：README 是“作者说法”，不是代码事实。

## 5.12 读源码的建议顺序

`scanner.py` 2000 行，不要顺序读。建议：

```text
1. Snapshot / TechHit / Manifest / ImportRef 数据结构
2. scan_repository 主流程
3. _should_skip_dir
4. _parse_requirements / _parse_package_json
5. catalog.lookup
6. _build_techs
7. detect_code_usages
8. _build_module_graph
9. _find_entry_points
```

每读一个函数，先问：

```text
输入是什么？
输出是什么？
失败会怎样？
```

## 5.13 动手：增加一项技术

打开 `repolens/catalog.py`，找同类条目，例如：

```python
T("Redis", "缓存与消息", ("redis", "redis-py"), "内存缓存", "any")
```

增加一个你知道的技术，例如：

```python
T("Meilisearch", "数据库", ("meilisearch",), "轻量全文搜索", "any")
```

注意：

- 分类必须在 `CATEGORIES` 中；
- aliases 写常见包名；
- 不要与已有别名冲突。

然后：

```powershell
..\.venv\Scripts\python.exe -m unittest discover -s tests -v
..\.venv\Scripts\python.exe scripts\evaluate.py
```

如果只改词典，通常不需要改扫描流程。

---

## 5.14 已知限制

- 动态 import / 运行时加载可能漏；
- 路径别名（`@/components`）可能无法解析；
- monorepo workspace 支持有限；
- 只读文件内容，不执行代码；
- 超大文件/仓库会截断；
- 技术词典不可能覆盖所有库。

这些限制会在报告中体现，而不是假装“全知”。
