# RepoLens 初学手册

> 面向 **Python 初学 + Agent 初学** 的完整项目导读。  
> 不是 API 手册，也不是“复制就能跑”的速查表，而是一条从“看懂”到“改得动”的路线。

---

## 这套文档适合谁

如果你符合下面任意一条，这套文档就是为你写的：

- 学过 Python 基础语法，但没读过 1000 行以上的真实项目；
- 听过 LangChain / Agent / RAG，但不知道一个 Agent 项目到底怎么落地；
- 能运行 RepoLens，但打开 `repolens/` 目录后不知道先看哪个文件；
- 想照着这个项目做一个自己的“代码分析 Agent”。

**不需要**你事先懂：

- LangChain、LangGraph；
- SSE、中间件、结构化输出；
- Vue 3、Vite；
- 代码扫描、依赖图。

这些概念都会在用到之前解释。

---

## 学完你能做到什么

完成全部章节后，你应该能够：

1. 说清 RepoLens 从浏览器输入到报告生成的完整调用链；
2. 独立读懂 `scanner.py` 中的扫描流程和技术证据结构；
3. 解释 Agent 的“模型 → 工具 → 结果 → 再思考”循环；
4. 知道什么时候该用规则扫描，什么时候该让模型判断；
5. 给项目增加一个技术词典条目、一个测试用例或一个扫描指标；
6. 判断一份 AI 报告里哪些是事实、哪些是推断、哪些无法核对；
7. 用现有测试和评测 Harness 验证自己的改动；
8. 照着这个架构做一个更小的、属于自己的 Agent 应用。

## 怎么读最有效

### 第一遍：只追一条请求

不要试图记住所有文件。只追一个问题：

> 我在首页输入 `examples/demo_shop`，为什么最后会看到一张技术卡片？

沿着这条线读：

```text
HomeView 输入
→ POST /api/analyze
→ server.start_run
→ pipeline.run_analysis
→ build_analysis_agent
→ tools / scanner
→ report.build_report
→ GET /api/report
→ ReportView
```

第一遍能把这根线讲清楚，就已经成功。

### 第二遍：带着问题读实现

例如：

- 为什么 Redis 能出现在技术栈里，而 README 里只写了一个词？
- 为什么报告里每条技术都有 `path:line`？
- 为什么有些技术标记“AI 推断”？
- 为什么没有 API Key 还能生成报告？

每读一章，至少回答一个这样的问题。

### 第三遍：改一个小东西

不要一上来改架构。先做这些低风险练习：

- 在 `catalog.py` 增加一项技术；
- 给扫描器增加一种入口文件名；
- 给报告加一个统计字段；
- 给评测加一个 fixture；
- 给前端改一处文案或空状态。

改完必须跑：

```powershell
..\.venv\Scripts\python.exe -m unittest discover -s tests -v
..\.venv\Scripts\python.exe scripts\evaluate.py
cd frontend
npm run build
```

## 约定

### 路径

除非特别说明，命令都在仓库根目录 `repolens/` 下执行。

项目根目录结构：

```text
repolens/                 ← 你现在的项目根
├── repolens/             ← Python 包
├── frontend/             ← Vue 源码
├── static/dist/          ← 已构建前端
├── examples/demo_shop/   ← 演示仓库
├── tests/
├── evals/
└── docs/
```

### 代码片段

教程里的代码是**简化后的真实代码**，用于说明结构；  
真正的实现以 `.py` / `.vue` 文件为准。每段都会给出源码路径。

### 术语

第一次出现的 Agent / Tool / SSE / HITL 等词，会先给一句人话解释，再进代码。  
完整术语表见第 15 章。

### 版本

本套文档对应当前基线：

- 分支：`main`
- 报告 schema：`3`
- 测试：43 个
- 评测：4 个仓库用例
- 前端：Vue 3 + Vite 6 + Less
- 后端：Python 3.11+ + LangChain / LangGraph

项目会继续演进，读到冲突时以当前代码为准，并回头修正文档。
