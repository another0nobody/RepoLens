```text
├── repolens/              Python 后端与 Agent

├── static/dist/           前端构建产物（已提交）
├── examples/demo_shop/    演示仓库
├── tests/                 标准库 unittest
├── evals/                 多仓库确定性评测
├── scripts/evaluate.py    评测 CLI
├── docs/                  文档与截图
├── data/                  运行时报告/克隆/SQLite（gitignore）
└── requirements.txt
```

### 为什么 `static/dist` 也提交

因为生产运行只需要 Python：

```text
python run.py
```

服务器直接托管 `static/dist`，不要求安装 Node。  
前端源码改动后必须重新 `npm run build`，否则 8765 仍然加载旧文件。

## 3.4 一次分析的完整链路

### 第一步：提交来源

```text
HomeView 输入 examples/demo_shop
→ POST /api/analyze
```

`server._handle_analyze()`：

```python
run = self.app.start_run(source)
```

`start_run` 会：

- 校验来源；
- 判断本地路径 / GitHub；
- 创建 `Run`；
- 启动后台线程；
- 返回 `run_id`。

### 第二步：后台线程开始

```text
server.start_run
→ threading.Thread(target=run_analysis)
→ pipeline.run_analysis(ctx)
```

注意：HTTP 请求立即返回，不会等分析完成。  
真正的工作在后台线程。

### 第三步：扫描

`pipeline.run_analysis()` 首先检查模型配置。

无论有没有 Key，都会需要扫描事实。Agent 工具会调用：

```python
scan_repository(root, source, source_type)
```

得到 `Snapshot`：

```text
files / languages / manifests / techs
entry_points / module_graph / top_dirs
```

### 第四步：Agent 分析

如果有 Key：

```text
build_analysis_agent(ctx)
→ create_agent(model, tools, middleware, response_format=RepoInsight)
→ agent.stream(...)
```

模型会：

```text
看仓库概览
→ 调 list_technologies
→ 调 inspect_technology
→ 调 read_project_file
→ 提交 RepoInsight
```

### 第五步：处理 HITL

如果 Agent 调用了 `clone_github_repository`：

```text
HumanInTheLoopMiddleware 暂停
→ pipeline 推送 interrupt 事件
→ 前端弹审批框
→ POST /api/hitl
→ pipeline 用 Command(resume=...) 恢复
```

拒绝则结束，不继续。

### 第六步：生成报告

```text
build_report(ctx, insight, ai_error)
→ 合并 Snapshot 事实 + RepoInsight 结论
→ normalize
→ save_report()
→ SQLite 索引
```

### 第七步：前端拿报告

```text
GET /api/report?run_id=...
```

前端 `ReportView` 渲染：

```text
先看什么 / 技术栈 / 模块 / 架构 / 学习 / 追问
```

## 3.6 线程与共享状态

一次分析不是单线程：

```text
主线程：HTTP 请求
后台线程：分析、扫描、Agent
前端：轮询/SSE
```

共享状态放在 `AnalysisContext`：

```python
ctx = AnalysisContext(
    run_id=...,
    source=...,
    source_type=...,
    bus=EventBus(...),
)
```

其中：

- `ctx.snapshot`：扫描结果；
- `ctx.emit()`：推事件；
- `ctx.checkpointer` / `ctx.store`：LangGraph 状态；
- `ctx.human_decision`：HITL 结果。

线程安全由 `EventBus`、锁/队列等保证。  
第 08 章会细讲。

## 3.7 前端的状态流

```text
store.js
├── view: home / run / report
├── run: 当前运行
├── report: 当前报告
├── events: SSE 事件
├── chat: 追问消息
├── drawers: 各种抽屉
└── codeViewer / adr / ...
```

组件不各自保存一份业务状态，而是：

```text
组件 → 调用 store action → 改 state → 所有组件响应
```

好处：

- 刷新可恢复；
- URL 可分享；
- SSE 重连只改一处；
- 抽屉/弹窗状态统一。
