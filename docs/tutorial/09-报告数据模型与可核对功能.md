# 第 09 章：报告数据模型与可核对功能

> 阅读时间：75–120 分钟  
> 前置：第 05/08 章  
> 目标：理解最终报告为什么长这样，以及风险、ADR、代码证据、引用核对分别建立在什么数据上

## 9.1 报告不是一段 Markdown

RepoLens 的报告是一个结构化 JSON：

```json
{
  "schema_version": 3,
  "run_id": "...",
  "repo_name": "demo_shop",
  "stats": {...},
  "languages": [...],
  "techs": [...],
  "module_graph": {...},
  "risks": [...],
  "learning_path": [...],
  "ai": {...}
}
```

前端不是“把模型回答显示出来”，而是按字段渲染。

这带来：

- 稳定的 UI；
- 可筛选/排序；
- 可对比；
- 可保存；
- 可做风险面板/ADR/代码证据。

---

## 9.2 build_report 合并了什么

源码：`repolens/report.py` 的 `build_report()`。

输入：

```text
ctx.snapshot   ← 扫描事实
insight        ← AI 结构化结论，可为 None
ai_error       ← AI 失败原因，可为 None
```

输出：

```text
report
```

合并规则：

```text
summary / highlights / architecture / risks / learning_path
  有 AI → 用 AI
  无 AI → 用 deterministic_* 规则生成

techs
  Snapshot 技术 + AI 技术解释/职责
  标记 ai_inferred

warnings
  扫描截断 / AI 失败 / AI 推断技术

module_graph / entry_points / manifests / languages
  直接来自 Snapshot
```

### 为什么要 deterministic 兜底

没有 Key 时，报告不能空白。  
`deterministic_summary()`、`deterministic_risks()` 等会根据扫描事实生成一个基础版本。

它不是 AI 的替代品，而是“至少能用”的报告。

---

## 9.3 schema_version 的作用

```python
REPORT_SCHEMA_VERSION = 3
```

当报告结构变化：

- 旧报告可能缺少新字段；
- 前端不能因为缺字段崩溃。

`normalize_report()` 会补齐：

```text
schema_version
tech.layer / tech.function
module_graph
...
```

所以：

> 报告格式可以演进，但旧报告仍然可读。

这是产品持久化很重要的一环。

## 9.4 技术（techs）

每项技术包含：

```json
{
  "key": "redis",
  "name": "Redis",
  "category": "缓存与消息",
  "layer": "数据与存储",
  "function": "提供数据缓存",
  "version": "5.0",
  "confidence": "高",
  "role": "用 Redis 缓存订单查询结果",
  "hint": "...",
  "modules": [
    {"path": "backend/app/cache.py", "line": 12, "snippet": "...", "role": "缓存客户端"}
  ],
  "evidence": [
    {"path": "backend/requirements.txt", "line": 4, "text": "redis==5.0", "kind": "依赖"}
  ],
  "key_modules": ["backend/app/cache.py"],
  "module_count": 2,
  "ai_inferred": false
}
```

- `role`：AI 解释或词典兜底；
- `modules`：代码证据；
- `evidence`：清单/import/配置原文；
- `confidence`：扫描/推断置信度；
- `ai_inferred`：是否是 AI 推断出来的技术。

## 9.5 证据代码查看器

源码：`repolens/codeview.py`。

API：

```text
GET /api/file?run_id=&path=&line=&context=
```

返回：

```json
{
  "path": "backend/app/main.py",
  "line": 10,
  "start": 2,
  "end": 18,
  "language": "Python",
  "lines": [
    {"number": 10, "text": "from app.db import init_db", "highlight": true}
  ],
  "masked": false,
  "truncated": true,
  "total_lines": 27
}
```

安全措施：

- 路径必须 resolve 在仓库根内；
- 拒绝 `.env`、私钥、`.git` 等；
- 拒绝二进制；
- 文件上限 400KB；
- 单行截断；
- 内容脱敏。

前端：`CodeViewer.vue`。

## 9.6 报告 Diff

源码：`repolens/diff.py`。

API：

```text
GET /api/diff?base=&target=
```

比较：

- 技术增删/变化；
- 模块节点/边增删；
- 风险/架构/学习路径/警告增删；
- 统计变化；
- `same_repo`。

设计取舍：

```text
不把 role 文案变化算作技术变化
```

因为模型每次措辞不同，会造成大量噪声。

## 9.7 风险面板

源码：`repolens/risk.py`。

`build_risk_panel(report)` 聚合：

- 报告已有 `risks`；
- 循环依赖；
- 测试缺失；
- 低置信度 / AI 推断技术；
- CI 缺失；
- 扫描截断 / warnings。

返回：

```json
{
  "level": "medium",
  "score": 26,
  "counts": {"high": 0, "medium": 2, "low": 2},
  "total": 4,
  "findings": [...]
}
```

注意：

- 前端现在**不展示 score**，只展示总数 + 高/中/低计数；
- score 仍保留在 API 里，供内部排序/调试；
- 报告头“风险提示”统计用 `report.risks.length`；
- 风险面板可能补充结构化发现，所以两个数字可能略不同。

## 9.8 ADR / 技术选型

源码：`repolens/adr.py`。

`build_adr(report, tech_name)` 生成 Markdown：

- 背景；
- 决策；
- 同类方案；
- 后果；
- 证据；
- 使用模块；
- 待确认。

它不调用模型，只基于报告事实 + `catalog.CATALOG` 同类候选。

关键诚实点：

```text
仓库没有记录选型动机 → 不编造“为什么选它”
```

---

## 9.9 回答引用核对

源码：`repolens/grounding.py`。

`check_grounding(report, text)`：

- 从回答中提取 `文件:行号`；
- 文件必须在报告已知路径中；
- 行号对照报告证据；
- 不在报告证据中时，再用只读代码窗口确认真实行号；
- 返回 valid / partial / invalid。

前端：

```text
引用可核对 x/y
引用待核对 x/y
未引用文件 / 行号
```

它检查的是“引用是否存在”，不是“结论是否成立”。

---

## 9.10 语义深度核对

源码：`repolens/semantic.py`。

`POST /api/ground/semantic`：

- 取前 5 条带行号的引用；
- 读取引用附近代码；
- 让模型判断 `support / partial / unsupported`；
- 返回理由和关键代码行。

这是可选、按次调用，不自动运行。

注意：

- 模型判断仍可能错；
- 只依据引用行附近代码；
- 不是完整调用链分析。

## 9.11 学习路线

`learning_path` 是报告字段，来源：

- AI 生成；
- 或 deterministic 规则。

前端：

- 先看什么显示“30 分钟路线 · N 步”入口；
- 完整步骤在学习路线 Tab；
- 勾选进度保存在 `localStorage`：

```text
repolens-learning:<run_id>
```

不写入报告/数据库。

## 9.12 先看什么

`ReportView.readingGuide` 是前端派生：

- 入口文件；
- 依赖图核心文件；
- 关键技术；
- 首个风险；

它不新增后端字段。

## 9.13 持久化

SQLite：`data/repolens.db`。

主要表：

```text
runs       运行状态/来源/时间
events     SSE 事件
messages   追问历史
reports    报告索引
```

报告 JSON：`data/reports/<run_id>.json`。

两者关系：

- JSON 是完整报告；
- SQLite 是索引/状态/聊天/事件；
- 历史列表合并两者。

`data/` 不提交。
