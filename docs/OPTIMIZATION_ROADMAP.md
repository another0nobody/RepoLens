# RepoLens 优化路线图

> 记录日期：2026-10-27
> 范围：本地单机产品、Agent 工程质量、报告阅读体验与可新增模块。
> 当前设计状态：已选定 **Contact Sheet** 为最终基线；`design/type-index` 与 `design/field-map` 保留为备选记录。

## 一句话判断

RepoLens 的差异点是 **扫描事实 + 可核对证据 + Agent 解释**。
当前最需要补的不是更多页面，而是：

1. 选定一套设计基线；
2. 补齐测试、报告 schema 版本和持久化；
3. 增加 **模块依赖图** 和 **报告 Diff**。

## 当前状态摘要

- 已实现：本地/GitHub 扫描、Agent 分析、报告、技术栈、模块地图、架构、追问、技术深挖、历史、导出、分享链接、HITL。
- 技术栈已经支持：层级 → 功能 → 技术（前端/后端/数据与存储/Agent / AI/语言与运行时/基础设施/工程效率）。
- 技术识别已经支持：清单、import、代码使用（`RedisCache`、`redis.Redis`、连接串等）、用途标签。
- 主要短板：
  - 没有自动化测试；
  - 报告字段没有 `schema_version`；
  - 运行状态、事件、聊天记忆只在内存；
  - 历史报告是文件扫描，没有索引；
  - 设计分支有 3 套，尚未收敛；
  - 层级图是技术层级，不是代码模块依赖图。

## 一、程序优化

### P0：质量与可维护性

#### 1. 自动化测试

- Scanner 单元测试：清单、import、代码使用、忽略目录、截断、路径安全；
- 固定 fixture 仓库 + golden report JSON；
- SSE 集成测试：analyze → events → report → chat；
- 前端关键路径 E2E：首页 → 运行 → 报告 → 技术栈/层级图 → 抽屉 → 追问；
- CI 顺序：`compileall` → 后端测试 → `npm run build` → 密钥扫描。

#### 2. 报告 Schema 版本化

- 报告根字段增加 `schema_version`；
- 新增字段时写迁移/补全函数；
- 旧报告明确支持的版本范围；
- golden report 跟随版本更新。

#### 3. AI 事实校验层

- AI 技术结论必须能落到 evidence/module；
- 无法落地的内容自动降级为“AI 推断”；
- 校验技术名、版本、文件路径；
- 输出“证据覆盖率”和“推断数量”，而不是只看报告是否生成。

### P1：Scanner 深化

#### 4. 多语言 AST

- Python 已有 AST；下一步用 tree-sitter 覆盖 JS/TS/Go/Java/Rust；
- 支持动态 import、路径别名、monorepo workspace；
- 区分“声明依赖”和“实际使用依赖”；
- 识别未使用依赖、间接依赖和 lockfile 版本。

#### 5. 增量扫描

- 文件 hash/mtime 缓存；
- 只重扫变化文件；
- 为报告 Diff 和 Watch 模式打基础；
- 降低大仓库扫描时间与 token 成本。

#### 6. 更细的技术用途

- Redis：缓存 / 会话 / 限流 / 消息 / 向量；
- PostgreSQL：主存储 / 只读副本 / 测试库；
- React：页面 / 组件库 / SSR；
- 每项判断带置信度，不用单一布尔值。

### P1：Agent 与运行时

#### 7. 仓库内容 Prompt Injection 防护

- 明确分隔系统指令、用户问题、仓库内容；
- 工具结果限制长度并标注来源；
- 禁止把 README/注释当系统指令；
- 对 `read_project_file` 的返回内容做指令剥离或明确不可信标记。

#### 8. 持久化与恢复

- SQLite 保存 run 状态、event log、LangGraph checkpointer、chat thread、报告索引；
- 报告 JSON 继续作为导出格式，但不再是唯一存储；
- 支持运行恢复、取消和失败重试。

#### 9. Agent 评测 Harness

- 固定 10~20 个仓库；
- 标注 expected techs、module paths、risks；
- 评测 scanner precision/recall、引用准确率、回答 groundedness；
- 每次改 prompt/规则都能回归。

### P2：API 与可观测性

- SSE 支持 `Last-Event-ID`、断线续传、取消运行；
- 每次 run 记录耗时、token、工具次数、扫描截断率、AI 失败率；
- 结构化日志和最小指标；
- 报告读取缓存，避免重复解析大 JSON。

## 二、设计优化

### 1. 收敛设计分支

- 三套世界都成立，但产品不能长期并行维护三套主界面。
- 推荐以 **Contact Sheet** 为基线；
- 吸收 **Type Index** 的“证据深度轴”；
- 吸收 **Field Map** 的“层级路线”表达；
- 最终保留一套设计系统；其余两套作为备选记录，不继续增加功能。

### 2. 层级图增强

当前层级图已经完成“层级 → 功能 → 技术”和中间分叉。

下一步：

- 缩放 / 平移；
- 层级、功能节点可折叠；
- 搜索定位并高亮路径；
- 图例与边颜色可读性检查；
- 移动端纵向树支持折叠；
- 提供“表格视图”作为无障碍替代。

### 3. 报告阅读路径

- 报告头部增加“先看什么”：核心 3 个文件、3 项技术、主要风险、30 分钟阅读路线；
- 把 `learning_path` 从列表变成可交互 checklist；
- 新手模式与维护者模式可有不同默认展开程度。

### 4. 证据浏览体验

- 点击证据打开只读代码片段查看器；
- 高亮对应行；
- 一键复制 `path:line`；
- 可选打开本地编辑器（明确是本地行为）；
- GitHub 来源跳到对应文件/行。

### 5. 空态、错误态、部分成功态

- 无 AI Key：说明规则报告仍可用；
- 扫描截断：漏了哪些目录、如何缩小范围；
- GitHub 克隆失败：区分网络、权限、仓库不存在、超时；
- 没有测试/数据库/CI：显示“未发现”，不要留空白；
- 旧报告缺字段：提示重新分析。

### 6. 交互效率

- `Cmd/Ctrl + K` 命令面板：技术、文件、模块、报告；
- URL 保存 tab、分类、搜索、分组/层级图状态；
- 分享链接保留当前视图；
- 键盘导航：技术行、层级图节点、抽屉；
- 搜索支持 `path:`、`layer:`、`function:`。

### 7. 可访问性

- 层级图节点键盘焦点和 `aria-label`；
- 图表不能只靠颜色区分层级；
- 图提供表格 fallback；
- 对比度、减少动效、焦点环持续检查。

## 三、可新增模块

按价值排序：

1. **模块依赖图 / 仓库架构图**
   - 文件 → 文件、模块 → 模块、前端 → 后端接口、数据层 → 存储；
   - 目录聚合、边过滤、搜索高亮；
   - 循环依赖、孤立模块、热点模块；
   - 这是从“技术栈报告”升级为“仓库地图”的关键。

2. **报告 Diff**
   - 对比两个 run：技术、模块、依赖、风险、架构、学习路径；
   - 服务回访用户和持续维护场景；
   - 可先基于现有 JSON 实现，不需要新存储。

3. **证据 / 代码查看器**
   - 只读文件片段、行号、语法高亮、证据标记；
   - 不执行仓库代码。

4. **风险与供应链面板**
   - 过期依赖、未使用依赖、敏感配置、缺失测试、CI、许可证；
   - 只做“提示 + 证据”，不要承诺完整安全审计。

5. **前 30 分钟学习路线**
   - 可交互 checklist；
   - 每步解释“为什么读这里”；
   - 本地保存进度。

6. **ADR / 技术选型记录生成器**
   - 基于报告和技术深挖生成“为什么选它、替代方案、代价、风险”；
   - 明确区分事实与推断；
   - 导出 Markdown。

7. **静态报告导出**
   - 单文件 HTML / PDF；
   - 分享前脱敏路径和密钥。

8. **Watch 模式**
   - 监听 git/文件变化，自动重扫并和上次报告 Diff。

9. **插件式检测器**
   - 新语言、框架、风险规则；
   - 需要先稳定 scanner 接口和测试。

暂不优先：账号、团队批注、远程协作、多租户。当前产品定位是本地单机，这些会显著增加持久化、权限和安全复杂度。

## 五、衡量指标

- 扫描：技术 recall / precision、证据覆盖率、截断率、扫描耗时；
- Agent：引用准确率、groundedness、工具调用次数、token/成本；
- 报告：从打开到找到第一个核心文件的时间、追问满意度；
- 设计：390px 可用性、键盘可达、层级图可读性、视图切换使用率；
- 运行：失败率、恢复成功率、SSE 断线恢复率。
