## 0. 文档约定

### 0.1 优先级

| 优先级 | 含义 | 修改规则 |
| --- | --- | --- |
| **P0** | 核心承诺；缺失会让产品不成立 | 删除/降级必须人类明确批准 |
| **P1** | 重要体验；缺失明显降低可用性 | 可以优化，但不能无说明地移除 |
| **P2** | 辅助能力/内部能力 | 可调整，但需更新文档 |

### 0.2 状态

- **已实现**：当前代码可运行并通过人工验收；
- **部分实现**：有基础能力但有明确限制；
- **未实现**：仅在未来规划中。

本文默认所有条目为“已实现”，例外会标注。

### 0.3 事实来源

- 功能以当前代码与 UI 为准；
- 验收标准描述**用户可观察的行为**，不绑定具体实现；
- 修改 API/报告字段/事件时，代码、本文、代码文档三处必须同步。

## 1. 产品定义

### 1.1 一句话

输入一个本地代码仓或 GitHub 仓库，得到一份**可核对、可追问、可学习**的中文技术栈报告。

### 1.2 要解决的问题

- 新接手一个仓库时，不知道用了哪些技术、各自负责什么；
- 依赖清单只能说明“装了什么”，不能说明“哪里用了”；
- 通用代码搜索/大模型问答容易编造文件路径和技术；
- 初学者需要一份能按顺序读源码的学习路线；
- GitHub 克隆属于有副作用操作，不能默认自动执行。

### 1.3 目标用户

1. **初学者 / 学生**：想通过一个真实项目理解 LangChain Agent、工具、结构化输出、中间件、HITL、记忆；
2. **需要快速熟悉仓库的开发者**：希望从技术栈、模块、架构、风险快速建立地图；
3. **教学者 / 面试准备者**：需要可运行、可讲解、可扩展的示例项目。

### 1.4 核心价值

- **事实优先**：扫描器先产出确定事实，AI 只做解释，不替代扫描；
- **可核对**：每项技术有版本、置信度、依赖/import 证据、模块路径；
- **可降级**：没有 Key 或模型失败时，本地仓库仍能生成规则报告；
- **有边界**：只读、脱敏、克隆需审批、默认本地监听；
- **可学习**：报告本身包含架构解读、风险、学习路径，UI 内有知识点讲解。

## 2. 目标与非目标

### 2.1 目标（当前版本）

- 支持本地目录与公开 GitHub 仓库；
- 识别 12 类、250+ 常见技术；
- 报告精确到“哪个文件、哪一行、导入了什么”；
- 提供实时分析过程（阶段、待办、工具、Token）；
- 提供报告追问；
- 提供 HITL 克隆审批；
- 支持历史、导出、分享链接、深色/浅色主题、移动端；
- 只装 Python 即可运行已构建的前端。

### 2.2 非目标（当前版本明确不做）

- 不做登录、多租户、权限系统；
- 不做 SaaS/公网部署加固；
- 不做私有仓库 OAuth / GitHub App；
- 不做 GitLab/Bitbucket 克隆（本地路径可绕过）；
- 不做数据库存储；
- 不做完整 AST/类型系统/跨文件数据流分析；
- 不做自动修改代码、自动提交 PR；
- 不做 PDF 导出、国际化、完整 WCAG 认证；
- 不承诺 100% 识别所有技术；未知依赖进入“其他依赖”。

## 3. 用户体验原则

1. **先事实后解释**：AI 不能编造扫描结果中不存在的文件路径/技术；
2. **过程可见**：长任务不能只有转圈，要显示阶段、工具和进度；
3. **失败可理解**：错误信息要说人话，并给出下一步；
4. **危险操作必须确认**：克隆 GitHub 前必须 HITL；
5. **不阻塞**：分析中可以离开页面，后台继续；
6. **可恢复**：刷新页面能通过 `?run` / `?report` 恢复；
7. **信息分层**：概览 → 分类 → 技术卡片 → 抽屉证据，避免一屏塞满；
8. **默认安全**：只读、脱敏、本地监听、不上传整仓。

## 4. 功能需求

### 4.1 来源与输入（SRC）

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| SRC-01 | P0 | 支持本地目录分析 | 输入绝对路径或相对路径；存在且为目录才可开始；启动后能扫描并生成报告 |
| SRC-02 | P0 | 支持公开 GitHub 仓库 | 支持 `https://github.com/owner/repo`、`owner/repo`、`.git`；克隆前弹审批；批准后扫描 |
| SRC-03 | P0 | 拒绝危险本地路径 | 精确匹配的系统目录/磁盘根（如 `C:\Windows`、`C:\Users` 本身）被拒绝并显示原因；其子目录靠白名单约束，不启动分析 |
| SRC-04 | P1 | 相对路径解析 | 相对路径不存在时按项目根目录再找一次；`examples/demo_shop` 可直接用 |
| SRC-05 | P1 | GitHub/本地歧义处理 | 本机存在同名相对目录时优先本地；否则两段式按 GitHub 简写处理 |
| SRC-06 | P1 | 内置示例 | 首页展示 3 个示例：内置 demo_shop、本项目核心代码、GitHub requests |
| SRC-07 | P1 | 输入校验 | 空输入提示；长度 >500 拒绝；非法路径 400；同时最多 2 个运行 |
| SRC-08 | P2 | 引号/环境变量 | 本地路径接受首尾引号；支持 `~`、环境变量展开 |

### 4.2 扫描与技术识别（SCN）

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| SCN-01 | P0 | 确定性扫描 | 不依赖大模型即可产出文件数、代码行、语言、清单、import、技术列表 |
| SCN-02 | P0 | 依赖清单解析 | 支持 requirements/pyproject/setup/Pipfile/package.json/pom/gradle/go.mod/Cargo/composer/Gemfile/csproj/Dockerfile/compose 等 |
| SCN-03 | P0 | import 解析 | Python/JS/TS/Java/Kotlin/Go/Rust/Ruby/PHP/C/C++ 至少可识别常用 import；Notebook 可解析 |
| SCN-04 | P0 | 技术证据 | 每项技术有 sources、evidence、modules；证据含路径/行号/原文/类型 |
| SCN-05 | P0 | 模块定位 | 模块精确到文件:行号，含代码片段和角色（入口/接口层/数据模型/测试等） |
| SCN-06 | P0 | 版本与置信度 | 版本来自清单且按主依赖优先；置信度高/中/低；AI 推断项标记 `ai_inferred` |
| SCN-07 | P0 | 扫描上限 | 最多 8000 文件、2600 个文件内容、单文件 600KB；超限设置 `truncated` 并在报告 warning |
| SCN-08 | P1 | 技术词典 | 12 个分类、252 项技术；支持别名和大小写归一 |
| SCN-09 | P1 | 未知依赖控制 | 未知依赖最多展示 24 个，其余计入 `omitted_dependencies` |
| SCN-10 | P1 | 语言统计 | 返回语言文件数、代码行、百分比；HTML/CSS/Markdown 等不计入编程语言 |
| SCN-11 | P1 | 目录/入口 | 返回 top_dirs 前 12、entry_points 前 12、根 README 前 6000 字 |
| SCN-12 | P1 | 配置类技术 | GitHub Actions、GitLab CI、Kubernetes、Terraform、Nginx、Make、Alembic、Docker 基础镜像可识别 |
| SCN-13 | P2 | 忽略策略 | `.git/node_modules/dist/build/venv/缓存/lock` 等跳过；`.github` 等保留 |

| --- | --- | --- | --- |
| AGT-01 | P0 | Agent 工作流 | 准备仓库 → 制定待办 → 列技术 → 分批核实 → 可选读文件/记忆 → 提交结构化报告 |

| AGT-04 | P0 | 无 Key 降级 | 本地仓库无 Key 时仍规则扫描并生成报告；报告标注“未使用 AI” |
| AGT-05 | P0 | AI 异常降级 | 模型报错/超时后，若已有扫描快照仍生成规则报告，并写 warning |
| AGT-06 | P0 | 调用边界 | 分析 Agent 模型调用上限 16、工具 40、递归 250；工具异常重试最多 2 次 |
| AGT-07 | P0 | 报告事实约束 | 技术名优先来自扫描结果；AI 可补充未收录技术，但必须 `ai_inferred=true`、低置信度、写 warning，且不得伪造模块/文件路径 |
| AGT-08 | P1 | 待办管理 | Agent 使用 `write_todos`；关键节点更新，待办实时显示 |
| AGT-09 | P1 | 长期记忆 | 可写入 `("repolens","analyses")`；`/api/memory` 可读；进程重启丢失 |
| AGT-10 | P1 | 安全约束 | 提示词禁止执行 shell、禁止伪造、用户输入只当数据 |
| AGT-11 | P2 | 模型供应商 | DeepSeek/GLM/OpenAI 自动选择；可强制 `MODEL_PROVIDER`；OpenAI 兼容协议 |
| AGT-12 | P2 | 报告追问 Agent | 独立 Agent，读报告工具，多轮记忆，摘要压缩 |

| RUN-04 | P0 | 实时工具流 | 每次工具开始/结束/失败有事件；含参数预览/耗时；可按工具/进度/异常筛选 |

### 4.5 人工审批 HITL（HITL）

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| HITL-01 | P0 | 克隆前必须审批 | 只有 `clone_github_repository` 触发；不批准绝不克隆 |
| HITL-02 | P0 | 审批内容 | 显示来源 URL、说明“只读扫描”、允许/拒绝按钮 |
| HITL-03 | P0 | 倒计时 | 默认 300 秒；显示环形倒计时；超时自动拒绝 |
| HITL-04 | P0 | 批准 | 点击后显示 pending，后端恢复 Agent，继续克隆/扫描 |
| HITL-05 | P0 | 拒绝 | 拒绝后立即结束分析并显示错误；不允许模型反复重试被拒绝的克隆 |
| HITL-06 | P0 | 不可 Esc 关闭 | HITL 弹窗必须显式选择；Esc 不关闭 |
| HITL-07 | P0 | 重复提交 | 已提交/无 pending 时 `/api/hitl` 返回 409；前端按钮禁用 |
| HITL-08 | P1 | 状态事件 | `interrupt` / `interrupt_resolved` 驱动 UI；刷新后若已结束则显示错误/报告 |

### 4.9 数据与持久化（DATA）

| ID | 优先级 | 需求 | 验收标准 |
| --- | --- | --- | --- |
| DATA-01 | P0 | 报告持久化 | 每次成功报告写 `data/reports/<run_id>.json`；UTF-8、缩进 2 |
| DATA-02 | P0 | 报告读取 | 刷新/历史可读；JSON 损坏返回不存在，不崩溃 |

## 5. 状态机与时序

### 5.1 运行状态

```text
             POST /api/analyze
                     │
                     ▼
                 running
                /       \
        report saved    exception / no snapshot
              │                 │
              ▼                 ▼
            done              error

前端离开运行页（服务端仍 running）：
running --(leaveRun 确认)--> background（仅前端）
完成后再通过历史/深链接打开报告。
```

规则：

- 服务端只有 `running/done/error`；`background` 是前端本地状态；
- 最多 2 个 `running`；
- `done` 以 `ctx.report is not None` 为准；
- 线程异常会被转为 `error` 事件，不静默崩溃。

### 5.2 HITL

```text
idle
  │ clone 工具触发
  ▼
pending（SSE interrupt；倒计时 300s）
  ├─ approve → resume Agent → 继续
  ├─ reject  → 立即 error / 停止
  └─ timeout → 自动 reject / 停止
  ▼
resolved（SSE interrupt_resolved；关闭弹窗）
```

### 5.3 AI 降级

```text
有 Key?
 ├─ 否：本地 → 规则扫描 → 规则报告（warning）
 └─ 是：Agent
        ├─ 成功 → 事实 + AI → 报告
        ├─ 结构化输出失败 → 纠错重试
        └─ 异常 → 有快照则规则报告；无快照本地兜底/GitHub 错误
```

## 6. 非功能需求

### 6.1 性能

- 单仓库最多扫描 8000 个文件；内容解析最多 2600 个文件；
- 单文件读取最多 600KB；读文件工具最多 400KB；
- 单次分析通常 30–180 秒，取决于模型和仓库；
- 同时最多 2 个分析；
- 页面首屏不依赖后端即可渲染骨架；健康/示例异步加载。

### 6.2 可靠性

- 单个清单解析失败不影响整体扫描；
- 单个工具异常会重试最多 2 次，仍失败则把错误返回给 Agent；
- SSE 断线自动重连并补发；
- 报告 JSON 损坏时历史列表跳过该文件，不崩溃；
- 前端所有 fetch 失败都有 Toast/空态。

### 6.3 安全与隐私

见 §4.10；额外要求：

- 默认不监听公网；
- 不把完整仓库内容上传模型；
- 报告中的 `local_path` 属于本地敏感数据，不进入 Git/截图；
- 发布前必须跑密钥扫描并人工检查截图。

### 6.4 兼容性

- Python 3.11+；
- Node.js 20+（仅前端开发）；
- 现代 Chrome / Edge（支持 `color-mix`、ES2022、EventSource）；
- 桌面 1440px 与手机 390px 为验收尺寸；
- 暂不承诺 Safari/Firefox 全量视觉一致。

### 6.5 可维护性

- 后端按“配置/事件/扫描/工具/编排/报告/服务”分层；
- 前端按“视图/组件/store/api/styles”分层；
- 文档、需求 ID、代码位置保持可追溯；
- 新增/修改功能必须更新本文件。

## 7. 边界与异常场景

| 场景 | 期望行为 |
| --- | --- |
| 空输入 | 前端 Toast；后端 400 |
| 路径不存在 / 是文件 | 400，提示路径不存在/不是文件夹 |
| 系统目录 / 磁盘根 | 400，拒绝扫描 |
| 超过 2 个运行 | 429；前端提示等待 |
| GitHub 无 Key | 无法克隆；明确提示配置 Key |
| GitHub 克隆失败 | 错误信息含 git 摘要；不生成假报告 |
| HITL 拒绝 | 立即结束；错误信息可读 |
| HITL 超时 | 自动拒绝；错误信息说明超时 |
| HITL 无 pending 再提交 | 409；前端恢复按钮 |
| 刷新运行页 | `?run` 恢复；进程重启则 404 |
| 刷新报告页 | `?report` 从磁盘加载 |
| 报告 JSON 损坏 | 404/空态；不崩溃 |
| 扫描截断 | 报告 warning；统计显示 truncated |
| 无 import 的技术 | 卡片/模块地图显示“仅依赖/配置”提示 |
| AI 结构化输出不合法 | 中文纠错重试；最终失败降级 |
| AI 401/404/超时 | 规则报告 + warning；前端可用 |
| 追问无报告 | 409 |
| 追问无 Key | SSE error，可读提示 |
| 追问并发 | 后端串行；前端禁用发送 |
| 剪贴板不可用 | Toast 提示手动选择 |
| 窄屏 | 单列/隐藏次要信息；无横向滚动 |
| 主题切换 | 立即生效；刷新保持 |
| 事件重复 | 按 seq 去重 |
| 事件过多 | 服务端保留 4000；前端截断 800/160 |

## 8. Feature Freeze：必须保留的功能清单

> 这是防止“灾难性遗忘”的核心。任何 Agent 在重构/简化/换框架时，**不得在没有人类确认的情况下删除以下任一能力**。

### 8.1 P0 功能清单

- [ ] **SRC-01/02** 本地 + GitHub 两种来源；
- [ ] **SRC-03** 路径安全拒绝；
- [ ] **SCN-01~07** 扫描、清单、import、证据、模块、版本/置信度、上限；
- [ ] **AGT-01~07** Agent 流程、6 工具、结构化输出、无 Key/AI 异常降级、调用限制、事实约束；
- [ ] **RUN-01~09** 创建、状态、时间线、工具流、待办、Token、重连、恢复、后台、错误重试；
- [ ] **HITL-01~07** 克隆审批、倒计时、批准/拒绝、Esc 禁止、重复提交防护；
- [ ] **RPT-01~12** 报告、统计、摘要、技术卡、详情、筛选、模块地图、架构、警告、导出、分享、历史；
- [ ] **CHAT-01~05** 流式追问、报告依据、无报告/无 Key 错误、多轮记忆、历史报告追问；

- [ ] **API-01~06** 分析/SSE/报告/运行/历史/HITL/Chat/静态托管契约；
- [ ] **OPS-01~04** Python 3.11+、无 FastAPI、仅 Python 可运行、前端可构建。

### 8.2 特别容易被“简化”掉的东西

| 容易被删 | 为什么必须保留 |
| --- | --- |
| 技术详情抽屉 / 证据 | 报告的核心价值是“可核对”，不能只剩卡片标题 |
| 模块地图 / 行号 | 产品区别于普通依赖清单的关键 |
| 置信度 / AI 推断标记 | 防止把 AI 猜测当事实 |
| 无 AI 降级 | 没有 Key 的初学者仍能跑通 |
| HITL 拒绝立即结束 | 拒绝后不能让模型反复重试 |
| 事件流筛选 / 待办 / Token | 这是 Agent 学习价值的一部分 |
| 历史 / 导出 / 分享链接 | 报告不是一次性页面 |
| 双主题 / 响应式 | 已交付的 UI 契约 |
| 路径/敏感文件/脱敏 | 安全承诺，不是可选装饰 |
| 构建产物 `static/dist` | 只装 Python 的用户必须能运行 |

### 8.3 需求删除流程

1. 在 PR/变更说明中写明要删除的 ID；
2. 说明用户影响与替代方案；
3. 获得人类明确批准；
4. 更新 README、本文、代码文档、截图；
5. 更新验收测试。

未经批准的删除视为 **P0 回归**。

## 9. 验收场景

### 9.1 本地分析 happy path

**Given** 仓库存在 `examples/demo_shop`，有可用模型 Key

**When** 首页填入并开始分析
**Then**

- 进入运行页，显示阶段/待办/工具/Token；
- 完成后自动进入报告页；
- 报告至少 1 项技术、1 条模块证据；
- 技术卡可打开抽屉；
- 模块地图能显示文件:行号；
- 架构/风险/学习路径非空（AI 或确定性兜底）。

### 9.2 无 Key 本地降级

**Given** 没有 API Key

**When** 分析本地仓库
**Then**

- warning 说明仅规则扫描；
- 仍生成报告；
- 技术/模块/统计来自扫描器；
- 报告 badge 显示“未启用 AI”；
- 追问提示无 Key。

### 9.3 GitHub 批准

**Given** 有效公开 GitHub URL、Git 可用、网络可达

**When** 开始分析，在 HITL 点“允许克隆并继续”
**Then**

- 弹窗显示 URL/倒计时/按钮；
- 批准后继续克隆；
- 成功后报告 `source_type=github`；
- 克隆失败时错误可读。

### 9.4 GitHub 拒绝

**When** HITL 点“拒绝”

**Then**

- 弹窗关闭；
- 分析在数秒内进入 error；
- 错误说明用户拒绝；
- 不产生报告；
- 不继续重试 clone。

### 9.5 报告追问

**Given** 已完成报告

**When** 打开“追问”，输入“数据库和缓存分别用在哪里？”
**Then**

- 显示用户消息和流式助手消息；
- 状态显示工具/生成；
- 回答引用报告或文件；
- 完成后可继续问；
- 无报告/无 Key 有明确错误。

### 9.6 历史与导出

**When** 打开历史、点击报告、导出 Markdown/JSON

**Then**

- 历史显示摘要；

- 导出文件包含当前报告；
- 分享链接在新标签页可打开同一报告。

- 输入不存在路径 → 400/Toast，不进入运行页；

## 12. 术语表

| 术语 | 含义 |
| --- | --- |
| Agent | 会循环“思考 → 调工具 → 看结果”的大模型程序 |
| Tool | 暴露给模型的 Python 函数，由 docstring 说明用途 |
| Middleware | 在模型/工具调用前后插入逻辑的机制 |
| HITL | Human-in-the-loop，执行危险操作前等人类批准 |
| SSE | Server-Sent Events，服务器单向实时推送 |
| Snapshot | 一次扫描的完整事实 |
| TechHit | 扫描器对一项技术的记录 |
| 结构化输出 | 让模型按 Pydantic 模型字段提交结果 |
| 置信度 | 对“确实使用了该技术”的判断：高/中/低 |
| AI 推断 | 扫描未找到直接证据、由模型补充的技术（必须标记） |
| 短期记忆 | 同一 thread 的对话/状态，进程内 checkpointer |
| 长期记忆 | Store 中的跨会话记忆，进程内 InMemoryStore |
| 降级 | AI 不可用时改用规则扫描/规则报告 |
